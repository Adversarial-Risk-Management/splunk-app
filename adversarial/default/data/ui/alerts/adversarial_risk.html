The risk title. The field accepts alert tokens, for example $name$ for the alert name or $result.hosts$ for a field of the first result row. With "One risk per result row", use {{row.host}} for a field of each row. AI Suggest Score reads the title. Learn more

Optional text for the top of the description. The action always adds the alert name, the trigger time and a link to the search results. AI Suggest Score reads the description, so name the affected assets and the exposure.

The type of the risk. A missing safeguard is a control deficiency. A wrong setting is a configuration risk. A known defect in third-party software is a vulnerability.
Where the risk came from. The name must exist in your organization. The risk sources and the incident sources are separate lists. To see the risk sources, open Settings > Risks in the Adversarial platform.

Item tags for the risk, with a comma between tags. Each tag must exist in your organization. The platform does not create a tag, and it rejects the risk if a tag is unknown.

The status of the new risk.
The raw score of the reporting source. "From the alert severity" maps the Splunk severity of this alert: debug and info give Info, warn gives Low, error gives Medium, severe gives High, and fatal gives Critical. AI Suggest Score uses this field when the title and the description hold too little detail.

How likely the risk is to cause a threat objective to happen.
What the risk can cause if an attacker uses it. The platform derives the urgency from the likelihood and the impact, and the due date from the urgency SLA.

Why this likelihood applies.
Why this impact applies.

The actions that address the risk. The audience is the wider organization, so be specific.

The controls that are in place against the risk. Complete this field before the risk moves to Closed.

Fields from the search result to add to the description. Use a comma-separated list. A name can hold a wildcard, for example host_*.

Per alert: one risk from the first result row. Combine the rows with stats, or sort the key row first.
Per result row: one risk for each result row, up to Maximum risks. Use {{row.host}} for a field of each row. $result.host$ always reads the first row.
With the trigger "For each result", Splunk runs the action one time for each row, so both choices give one risk for each row.
For "One risk per result row" only. The limit for one alert trigger. The action skips the rows after the limit and logs a warning. Default: 25.

A comment gives the owner a direct link back to the Splunk results. AI Suggest Score reads the comments of a risk.
