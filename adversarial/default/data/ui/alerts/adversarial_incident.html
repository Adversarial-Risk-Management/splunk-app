The incident title. The field accepts alert tokens, for example $name$ for the alert name or $result.host$ for a field of the first result row. With "One incident per result row", use {{row.host}} for a field of each row. Learn more

Optional text for the top of the description. The action always adds the alert name, the trigger time and a link to the search results.

An empty severity stays empty until a person scores the incident in the platform, for example with AI Suggest Score. AI Suggest Score reads the title, the description and the comments. "From the alert severity" maps the Splunk severity of this alert: debug and info give SEV-5, warn gives SEV-4, error gives SEV-3, severe gives SEV-2, and fatal gives SEV-1.
Why this severity applies. The platform stores it with the score.

The status of the new incident.
Where the incident came from, for example SIEM. The name must exist in your organization. To see the list, open Settings > Incidents in the Adversarial platform.

Item tags for the incident, with a comma between tags. Each tag must exist in your organization. The platform does not create a tag, and it rejects the incident if a tag is unknown.

Fields from the search result to add to the description. Use a comma-separated list. A name can hold a wildcard, for example src_*.

Per alert: one incident from the first result row. Combine the rows with stats, or sort the key row first.
Per result row: one incident for each result row, up to Maximum incidents. Use {{row.host}} for a field of each row. $result.host$ always reads the first row.
With the trigger "For each result", Splunk runs the action one time for each row, so both choices give one incident for each row.
For "One incident per result row" only. The limit for one alert trigger. The action skips the rows after the limit and logs a warning. Default: 25.
